# NSTT

**زبان‌ها:** [English](README.md) | [فارسی](README-fa.md)


🚀 **نصب و مدیریت سرور dnstt با یک دستور**

اسکریپتی جامع برای نصب و مدیریت خودکار سرورهای تونل DNS با [dnstt](https://www.bamsoftware.com/software/dnstt) در سیستم‌های لینوکسی. این اسکریپت همه کارها را از نصب تا پیکربندی انجام می‌دهد و راه‌اندازی تونل DNS را ساده می‌کند.

NSTT نسخه امن‌تر و اصلاح‌شده [bugfloyd/dnstt-deploy](https://github.com/bugfloyd/dnstt-deploy) است، با اعتبارسنجی ورودی، خواندن امن فایل پیکربندی، قوانین فایروال بدون تکرار، پشتیبانی Dante بر اساس توزیع، بررسی تداخل پورت و اعتبارسنجی باینری در هر اجرا.

## تنظیم DNS دامنه

پیش از استفاده از این اسکریپت، باید رکوردهای DNS دامنه خود را درست تنظیم کنید:

### پیکربندی نمونه
- **نام دامنه شما**: `example.com`
- **آدرس IPv4 سرور شما**: `203.0.113.2`
- **آدرس IPv6 سرور شما**: `2001:db8::2` (اختیاری)
- **زیردامنه تونل**: `t.example.com`
- **نام هاست سرور**: `tns.example.com`

### تنظیم رکوردهای DNS
به پنل تنظیمات ثبت‌کننده دامنه خود بروید و این رکوردها را اضافه کنید:

| نوع | نام | اشاره به |
|------|------|-----------|
| A | `tns.example.com` | `203.0.113.2` |
| AAAA | `tns.example.com` | `2001:db8::2` (در صورت داشتن IPv6) |
| NS | `t.example.com` | `tns.example.com` |

**مهم**: پیش از تست تونل، منتظر انتشار DNS بمانید (ممکن است تا ۲۴ ساعت طول بکشد).

## ویژگی‌ها

- **پشتیبانی از چند توزیع**: Fedora، Rocky Linux، CentOS، Debian، Ubuntu
- **منوی مدیریت تعاملی**: رابط کاربری ساده برای همه عملیات
- **قابلیت به‌روزرسانی خودکار**: مکانیزم به‌روزرسانی داخلی اسکریپت، با اعتبارسنجی دانلود (دانلود خراب یا صفحه HTML هرگز جای اسکریپت نصب‌شده را نمی‌گیرد)
- **تشخیص خودکار**: سیستم‌عامل، معماری و پورت SSH
- **یکپارچگی با systemd**: ساخت و مدیریت سرویس اختصاصی systemd برای کارکرد قابل‌اعتماد، اجرای خودکار هنگام بوت و لاگ جامع
- **امنیت تقویت‌شده**: اجرای سرویس بدون کاربر روت با ویژگی‌های امنیتی systemd، دایرکتوری پیکربندی با مالکیت روت و محدودیت ری‌استارت تا پیکربندی خراب برای همیشه در حلقه نیفتد
- **پیکربندی هوشمند**: ذخیره تنظیمات و استفاده دوباره خودکار از کلیدها؛ فایل پیکربندی به‌عنوان داده خوانده می‌شود و هرگز به‌عنوان کد اجرا نمی‌شود
- **اعتبارسنجی ورودی**: زیردامنه باید نام DNS معتبر باشد و MTU باید عددی بین ۵۷۶ تا ۹۰۰۰ باشد
- **تونل انعطاف‌پذیر**: حالت SSH یا پروکسی SOCKS
- **آماده شبکه**: پیکربندی خودکار فایروال و iptables؛ قوانین فقط یک بار اضافه می‌شوند و پیش از بازنویسی قوانین ذخیره‌شده، از آن‌ها بکاپ گرفته می‌شود
- **بررسی تداخل پورت**: اگر پورت ۵۳ یا ۵۳۰۰ را سرویس دیگری گرفته باشد (مثل systemd-resolved)، نصب همان اول متوقف می‌شود و تونل بی‌صدا بدون دریافت کوئری نمی‌ماند
- **اعتبارسنجی باینری**: بررسی چک‌سام MD5 و SHA1 و SHA256 در هر اجرا، حتی برای باینری از قبل نصب‌شده؛ باینری نامطابق یا خراب دوباره دانلود می‌شود
- **Dante بر اساس توزیع**: در Debian و Ubuntu سرویس `danted` و در Fedora و Rocky و CentOS سرویس `sockd`، با فایل پیکربندی و بررسی سرویس متناظر
- **باینری‌های رسمی**: دانلود از [dnstt.network](https://dnstt.network)

## شروع سریع

### پیش‌نیازها
- سرور لینوکسی (Fedora، Rocky، CentOS، Debian یا Ubuntu)
- دسترسی روت یا sudo
- اتصال اینترنت برای دانلود بسته‌ها
- **نام دامنه با پیکربندی درست DNS** (به بخش تنظیم DNS دامنه در بالا نگاه کنید)

### نصب

**نصب با یک دستور:**
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Behzad9/NSTT/main/dnstt-deploy-fixed.sh)
```

این دستور:
1. ابزارهای گمشده (`curl` و `ip` و `ss` و `iptables`) را نصب می‌کند و ابزارهای لازم دیگر را بررسی می‌کند
2. اسکریپت را در مسیر `/usr/local/bin/dnstt-deploy` نصب می‌کند
3. بررسی می‌کند که پورت‌های ۵۳ و ۵۳۰۰ آزاد باشند
4. فرایند نصب تعاملی را شروع می‌کند
5. سرور dnstt شما را به‌صورت خودکار پیکربندی می‌کند

### استفاده پس از نصب

پس از نصب، می‌توانید سرور dnstt خود را با دستور نصب‌شده مدیریت کنید:

```bash
dnstt-deploy
```

این دستور منوی تعاملی با این گزینه‌ها را نشان می‌دهد:

1. **نصب یا پیکربندی دوباره سرور dnstt** - راه‌اندازی یا تغییر پیکربندی
2. **به‌روزرسانی اسکریپت dnstt-deploy** - بررسی و نصب به‌روزرسانی اسکریپت
3. **بررسی وضعیت سرویس** - مشاهده وضعیت فعلی سرویس
4. **مشاهده لاگ سرویس** - مشاهده لاگ زنده (برای خروج Ctrl+C)
5. **نمایش اطلاعات پیکربندی** - نمایش پیکربندی فعلی، کلید عمومی و دستورهای مدیریت
0. **خروج** - خروج از منو

### فرایند نصب

در هنگام نصب (گزینه ۱)، از شما این موارد پرسیده می‌شود:
- **زیردامنه نیم‌سرور** (مثل `t.example.com`)
- **مقدار MTU** (پیش‌فرض: 1232)
- **حالت تونل** (SSH یا SOCKS)

## پیکربندی

### حالت‌های تونل

**حالت SOCKS (گزینه ۱)**
- پروکسی SOCKS5 یکپارچه Dante را راه‌اندازی می‌کند
- روی `127.0.0.1:1080` گوش می‌دهد
- امکان پروکسی کامل اینترنت را فراهم می‌کند

**حالت SSH (گزینه ۲)**
- ترافیک DNS را به سرویس SSH شما تونل می‌کند
- پورت SSH را به‌صورت خودکار تشخیص می‌دهد (پیش‌فرض: 22)
- برای دسترسی امن شل از طریق DNS مناسب است
- با اپ‌های موبایل سازگار است

### تنظیمات MTU
- **پیش‌فرض**: 1232 بایت
- **بازه پذیرفته‌شده**: ۵۷۶ تا ۹۰۰۰ بایت (توسط اسکریپت اعمال می‌شود)
- **مقادیر پیشنهادی**:
    - شبکه‌های پایدار و سریع: 1400
    - شبکه‌های معمولی: 1232
    - شبکه‌های ناپایدار و کند: 1200

### تغییر تنظیمات
برای تغییر MTU یا تنظیمات دیگر:
1. دستور `dnstt-deploy` را اجرا کنید
2. گزینه ۱ (نصب یا پیکربندی دوباره سرور dnstt) را انتخاب کنید
3. هنگام پرسش، مقدارهای جدید را وارد کنید

اسکریپت به‌صورت خودکار پیکربندی را به‌روز می‌کند و سرویس‌ها را ری‌استارت می‌کند.

## استفاده کلاینت

### دانلود باینری کلاینت

باینری کلاینت dnstt مناسب پلتفرم خود را از [dnstt.network](https://dnstt.network) دانلود کنید:

**پلتفرم‌های رایج:**
- **لینوکس x64**: `dnstt-client-linux-amd64`
- **ویندوز x64**: `dnstt-client-windows-amd64.exe`
- **مک اینتل**: `dnstt-client-darwin-amd64`
- **مک اپل سیلیکون**: `dnstt-client-darwin-arm64`

### دستور اتصال

پس از راه‌اندازی سرور، کلید عمومی را دریافت می‌کنید. برای اتصال از آن استفاده کنید:

```bash
dnstt-client -udp DNS_SERVER_IP:53 -pubkey-file server.pub t.example.com 127.0.0.1:7000
```

#### DNS_SERVER_IP

آدرس IP سرور DNS به سیستم شما بستگی دارد:

**لینوکس**:
```bash
systemd-resolve --status | grep "DNS Servers"
```
گزینه‌های رایج: `127.0.0.53:53` یا `127.0.0.1:53` یا IP روتر شما

**ویندوز**:
```cmd
ipconfig /all | findstr /C:"DNS Servers"
```

**مک**:
```bash
scutil --dns | grep nameserver
```

همچنین می‌توانید از این موارد استفاده کنید:
- IP داخلی روتر یا مودم (مثل `192.168.1.1:53`)
- سرور DNS ارائه‌دهنده اینترنت شما
- سرورهای DNS عمومی مثل `8.8.8.8:53` یا `1.1.1.1:53` (در صورت در دسترس بودن)

## مدیریت

### منوی مدیریت

ساده‌ترین راه مدیریت سرور dnstt، منوی تعاملی است:

```bash
dnstt-deploy
```

این منو دسترسی سریع به این موارد را می‌دهد:
- پیکربندی دوباره سرور
- به‌روزرسانی اسکریپت
- نظارت بر وضعیت سرویس
- مشاهده لاگ زنده
- اطلاعات پیکربندی

### محل فایل‌ها

```
/usr/local/bin/dnstt-deploy             # اسکریپت مدیریت
/usr/local/bin/dnstt-server             # باینری اصلی
/etc/dnstt/                             # دایرکتوری پیکربندی
├── dnstt-server.conf                  # پیکربندی اصلی
├── {domain}_server.key                # کلید خصوصی (برای هر دامنه)
└── {domain}_server.pub                # کلید عمومی (برای هر دامنه)
/etc/systemd/system/dnstt-server.service  # سرویس systemd
```

### دستورهای دستی سرویس

اگر مدیریت با خط فرمان را ترجیح می‌دهید:

**سرویس dnstt-server**:
```bash
sudo systemctl status dnstt-server    # بررسی وضعیت
sudo systemctl start dnstt-server     # شروع سرویس
sudo systemctl stop dnstt-server      # توقف سرویس
sudo systemctl restart dnstt-server   # ری‌استارت سرویس
sudo journalctl -u dnstt-server -f    # مشاهده لاگ
```

**سرویس Dante SOCKS (فقط حالت SOCKS)**:

نام سرویس به توزیع شما بستگی دارد:

| توزیع | سرویس | فایل پیکربندی |
|--------------|---------|--------------------|
| Debian، Ubuntu | `danted` | `/etc/danted.conf` |
| Fedora، Rocky، CentOS | `sockd` | `/etc/sockd.conf` |

```bash
# Debian / Ubuntu
sudo systemctl status danted          # بررسی وضعیت
sudo systemctl start danted           # شروع سرویس
sudo systemctl stop danted            # توقف سرویس
sudo systemctl restart danted         # ری‌استارت سرویس
sudo journalctl -u danted -f          # مشاهده لاگ
```

```bash
# Fedora / Rocky / CentOS
sudo systemctl status sockd           # بررسی وضعیت
sudo systemctl start sockd            # شروع سرویس
sudo systemctl stop sockd             # توقف سرویس
sudo systemctl restart sockd          # ری‌استارت سرویس
sudo journalctl -u sockd -f           # مشاهده لاگ
```


## عیب‌یابی

### استفاده از ابزارهای داخلی

منوی مدیریت دسترسی سریع به ابزارهای عیب‌یابی را می‌دهد:

1. **بررسی وضعیت سرویس** (گزینه ۳ منو): نشان می‌دهد سرویس‌ها درست کار می‌کنند یا نه
2. **مشاهده لاگ سرویس** (گزینه ۴ منو): نظارت زنده بر لاگ سرویس
3. **نمایش اطلاعات پیکربندی** (گزینه ۵ منو): نمایش پیکربندی فعلی و کلید عمومی

### خطاهای اندازه MTU

اگر خطایی مثل این دیدید:
```
FORMERR: requester payload size 512 is too small (minimum 1232)
```

MTU را حداقل به عدد گفته‌شده افزایش دهید:
1. دستور `dnstt-deploy` را اجرا کنید
2. گزینه ۱ (نصب یا پیکربندی دوباره سرور dnstt) را انتخاب کنید
3. هنگام پرسش، مقدار MTU پیشنهادی را وارد کنید (مثل 1232)

به معایب کارکردی استفاده از MTU خیلی پایین توجه کنید.

### مشکلات رایج

**سرویس شروع نمی‌شود**:
```bash
dnstt-deploy  # با گزینه ۳ منو وضعیت را بررسی کنید
# یا دستی:
sudo systemctl status dnstt-server    # بررسی وضعیت سرویس
sudo journalctl -u dnstt-server -n 50 # بررسی لاگ برای خطا
ls -la /usr/local/bin/dnstt-server    # بررسی مجوزهای باینری
```

**پورت از قبل در حال استفاده است**:
اگر نصب با پیام «Port 53 is already in use» یا «Port 5300 is already in use» متوقف شد، سرویس دیگری آن پورت را گرفته است. با این دستور بررسی کنید:
```bash
sudo ss -tulnp | grep -E ":(53|5300)[[:space:]]"
```
در بسیاری از سیستم‌ها مقصر روی پورت ۵۳، سرویس systemd-resolved است که روی `127.0.0.53:53` گوش می‌دهد. اول آن سرویس را متوقف یا دوباره پیکربندی کنید، بعد نصب را دوباره اجرا کنید. شنونده نصب قبلی خود dnstt-server روی پورت ۵۳۰۰ مانع پیکربندی دوباره نمی‌شود.

**خطا در اعتبارسنجی باینری**:
اگر نصب خطای عدم تطابق چک‌سام گزارش کرد، باینری دانلودشده نصب نشده و باینری نصب‌شده قبلی دست نخورده باقی مانده است. اتصال شبکه خود را بررسی کنید و دوباره تلاش کنید؛ باینری را از منبع نامعتبر نصب نکنید.

**زیردامنه یا MTU نامعتبر**:
نصب فقط زیردامنه DNS معتبر (مثل `t.example.com`) و MTU بین ۵۷۶ تا ۹۰۰۰ را می‌پذیرد. ورودی نامعتبر رد می‌شود و دوباره پرسیده می‌شود، پس تایپ اشتباه نمی‌تواند پیکربندی یا سرویس systemd را خراب کند.

**Dante شروع نمی‌شود (حالت SOCKS)**:
```bash
sudo systemctl status danted    # Debian / Ubuntu
sudo systemctl status sockd     # Fedora / Rocky / CentOS
sudo journalctl -u danted -n 50 # Debian / Ubuntu
sudo journalctl -u sockd -n 50  # Fedora / Rocky / CentOS
```
رایج‌ترین علت، اینترفیس خارجی اشتباه است. نصب حالا پیش از پایان بررسی می‌کند که Dante واقعا در حال اجراست؛ اگر نشد، اینترفیس یا پیکربندی Dante را اصلاح کنید و نصب را دوباره اجرا کنید.

**مشکلات پیکربندی DNS**:
```bash
dig @YOUR_SERVER_IP t.mydomain.com           # تست تونل DNS (از سمت کلاینت)
sudo iptables -t nat -L PREROUTING -n -v     # بررسی قوانین iptables
```

**مشکلات پروکسی SOCKS**:
```bash
curl --socks5 127.0.0.1:1080 http://httpbin.org/ip  # تست پروکسی SOCKS به‌صورت محلی
sudo cat /etc/danted.conf                           # بررسی پیکربندی Dante (Debian / Ubuntu)
sudo cat /etc/sockd.conf                            # بررسی پیکربندی Dante (Fedora / Rocky / CentOS)
```

**بررسی پورت**:
```bash
sudo ss -tulnp | grep 5300  # بررسی پورت dnstt-server
sudo ss -tulnp | grep 1080  # بررسی پورت پروکسی SOCKS (در صورت فعال بودن)
```

## ویژگی‌های پیشرفته

### پشتیبانی از چند دامنه

اسکریپت با ساخت جفت کلید جداگانه برای هر دامنه، از چند دامنه پشتیبانی می‌کند. اما چون همه پیکربندی‌ها از پورت ۵۳ برای ترافیک DNS استفاده می‌کنند، فقط یک پیکربندی دامنه می‌تواند هم‌زمان فعال باشد. برای جابه‌جایی بین دامنه‌ها:

1. دستور `dnstt-deploy` را اجرا کنید
2. گزینه ۱ (نصب یا پیکربندی دوباره سرور dnstt) را انتخاب کنید
3. هنگام پرسش، زیردامنه جدید را وارد کنید

### پشتیبانی DoH و DoT

برای پیکربندی DNS-over-HTTPS (DoH) یا DNS-over-TLS (DoT)، به [مستندات رسمی dnstt](https://dnstt.network) مراجعه کنید.

### نظارت بر کارکرد

از نمایشگر لاگ داخلی (گزینه ۴ منو) یا دستورهای دستی استفاده کنید:

```bash
sudo ss -tulnp | grep -E "(5300|1080)"        # نظارت بر تعداد اتصال
sudo systemctl status dnstt-server            # بررسی منابع سرویس
sudo journalctl -u dnstt-server -f --no-pager # نظارت بر لاگ برای خطا
```
